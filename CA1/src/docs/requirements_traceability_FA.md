# تطبیق با صورت پروژه

اولویت طبق دستور کاربر: `spec.pdf` و `HW1.pdf` بر گزارش‌ها و Specification قدیمی داخل ZIP مقدم‌اند. نسخه جاری این تقدم را اعمال می‌کند؛ oracle قدیمی معیار پاس طراحی اصلاح‌شده نیست.

| الزام | پیاده‌سازی | شاهد بررسی |
|---|---|---|
| ورودی 28×28، FC1 با 8 و FC2 با 10 نورون | پیش‌فرض Top و suite اصلی | ۱۱ تصویر و بررسی همه hidden/logitها |
| همه حساب‌ها FP16 مطابق IEEE 754 | هسته‌های ADD/MUL، RNE، subnormal، infinity و canonical NaN | ۲۹۷٬۰۰۸ بردار برای هر سه عمل ADD/MUL/ReLU |
| یک ADD و یک MUL ممیز شناور | تنها نمونه‌ها در Datapath | hierarchy و audit با شمارش نمونه |
| SRAM هفت سیکل، ردیف 112 بیتی/۷ کلمه | row_sram با پیش‌فرض رسمی | بررسی ۹۰۸ ردیف وزن و ۱۱۲ ردیف تصویر با متادیتا و تأخیر |
| نگهداری هفت مقدار پاسخ | یک RowStage وزن و یک RowStage تصویر | تست hold، consume و replacement هم‌لبه |
| تولید محصول در هر سیکل پردازش معتبر | MUL ترکیبی + ProductRegister | scoreboard تعداد و ترتیب termها |
| دو بانک Ping-Pong هفت‌خانه‌ای | دو آرایه داده و متادیتا، seal/occupancy مستقل | گروه کامل/ناقص، توقف مصرف، FIFO، metadata و reset |
| تعویض بدون تخریب داده خوانده‌نشده | بانک seal شده تا مصرف پایان گروه آزاد نمی‌شود | تست پرشدن دو بانک و blocked output |
| خواندن گروه تکمیل‌شده | rd_valid نیازمند sealed است | تست منع read برای گروه باز؛ cut-through حذف شده |
| جمع انباشتی با ترتیب ثابت | یک acc برای FC1 و acc مقصددار برای FC2 | مدل Python نورون‌به‌نورون، مستقل از mapping SRAM |
| بایاس پس از آخرین محصول | bias_pending با همان ADD | ۱۸ ADD جداگانه، مقایسه تمام logitها و hiddenها |
| ReLU تنها بعد FC1 | relu_fp16 پیش از نوشتن hidden | مقایسه هشت activation هر اجرا |
| RF ده‌خانه‌ای قابل بازاستفاده | activation_regfile با عمق رسمی ۱۰ | شرط آخرین خواندن hidden و یک نوشتن نهایی موازی |
| ده خروجی موازی و done | باس 160 بیت، Argmax و FSM DONE یک‌سیکل | تست خروجی و پایداری بعد پایان |
| شمار سیکل مؤثر در نمره | prefetch و pipeline تک‌منبعی حفظ شده | گزارش واقعی ۶۴۰۳ سیکل، بدون تغییر رفتار مقرر |
| تصاویر دیتاپث و FSM در کنار کد | PNG و SVG قابل بازتولید | بررسی تصویری و تطبیق خودکار پورت‌ها/گذارها |
| ماژولاریتی و تمیزی | ۱۷ فایل هم‌نام ماژول، یک منبع RTL | عدم تعریف تکراری/ماژول بلااستفاده، پارامترهای Top |
| زبان، ابزار و reset مشخص | Verilog-2005، sync active-high، قواعد معتبر/نامعتبر | context و معماری جاری |
| پلن و Step متناظر تسک ۵ | 05_plan و ۱۷ پلن هم‌نام | استخراج و تطبیق Stepهای کد و برنامه جاری |
| اجرای TB و ثبت debug | log واقعی و evaluator | regression، guard منفی و خطاهای رفع‌شده |
| اجرای قابل تغییر در خود ModelSim | تنظیمات ابتدای TB و `run_modelsim.do` بدون Python | تست بدون plusarg، تغییر ورودی/ابعاد/ریست، guardها و کنترل ۸۷ مسیر Wave؛ اجرای واقعی ModelSim در این محیط انجام نشده |

اعداد فوق نتایج تست‌اند و ادعای اثبات رسمی همه زوج‌های FP16، سنتز یا اجرای ModelSim نیستند. هسته‌ها پرچم exception یا انتخاب rounding mode ندارند، زیرا در صورت پروژه درخواست نشده‌اند.

## تفاوت‌های عمدی اصلاح‌شده

| نسخه ورودی | نسخه جاری مطابق PDF | اثر |
|---|---|---|
| شروع accumulation از bias | شروع از صفر و افزودن bias در انتها | ۸۷ کلمه از ۱۱۰ logit این مجموعه نسبت به oracle قدیمی تغییر می‌کند؛ همه کلاس‌ها حفظ می‌شوند |
| read از بانک هنوز باز | read تنها پس از seal | حذف cut-through و بازتنظیم prefetch |
| preload ده bias FC2 | صفرکردن acc و جمع جداگانه bias | جمع‌ها ۶۳۷۰، ضرب‌ها ۶۳۵۲ |
| ۶۳۶۷ سیکل | ۶۴۰۳ سیکل | افزایش ۳۶ سیکل برای رعایت رفتار مقرر |
| انتخاب نوع SRAM با DEPTH | SOURCE_KIND صریح در اتصال | تغییر ابعاد حافظه رفتار نوع را عوض نمی‌کند |
| مسیر فایل FC2 ثابت در بدنه | پارامتر Top به leaf | امکان تغییر فایل از TB |
| شمارنده‌های آدرس تکراری و پورت‌های بی‌مصرف | مالک یکتا و رابط‌های جاری تولیدشده از RTL | کمترشدن خطر ناسازگاری |

## وضعیت قالب‌های HW1

این تحویل ادامه بازآرایی پیاده‌سازی جاری است؛ سوابقی که در فایل ورودی وجود نداشتند به گذشته نسبت داده نشده‌اند.

| بخش HW1 | سند/خروجی جاری | وضعیت |
|---|---|---|
| تسک ۱: Context | `01_context.md` | توصیف جاری فراهم است |
| تسک ۲: تقسیم‌بندی، header و نمودار | interfaces، architecture.json و hierarchy/datapath | جاری و منطبق با کد؛ `submission/sub_modules.zip` شامل header، تقسیم‌بندی و تصاویر است |
| تسک ۳: Spec هر ماژول | architecture، interfaces و plans | قرارداد جاری و موارد مرزی مستند است؛ نسخه قدیمی معیار رفتار نیست |
| تسک ۴: پرامپت ساده/ساختاریافته، دو خروجی و مقایسه | در ZIP ورودی موجود نبود | تاریخچه و خروجی دو پرامپت ساخته یا جعل نشده است؛ برای تحویل کامل آن بخش باید سوابق واقعی افزوده شوند |
| تسک ۵: 05_plan.md و 05_code.v | `export_task5.py` | از منابع یکتا تولید و کامپایل خروجی کنترل می‌شود |
| تسک ۶: Planner/Programmer/Reviewer/Evaluator | برنامه جاری، RTL، `06_3_reviewer.md` و `06_4_evaluator.md` | بازبینی و لاگ اجرای واقعی موجود است؛ ادعای گفت‌وگو یا مدل مستقل بدون سابقه نمی‌شود |

نام نهایی تحویل رسمی طبق HW1 باید `CAD_CA1_<SID1>_<SID2>.zip` باشد. شناسه دانشجویی، نام اعضا و پرامپت‌های ثبت‌شده در ورودی نبودند؛ اطلاعاتی برای آن‌ها اختراع نشده است.
