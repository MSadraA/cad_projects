# CAD CA2 - فاز اول | سنتز دستی با Actel

شناسه‌ها: **810102420** و **810101469**

این بسته شامل بازطراحی ساختاری جمع‌کننده FP16، ضرب‌کننده FP16 و بافر پینگ‌پنگ است. طراحی به صورت سلسله‌مراتبی انجام شده و برگ‌های سخت‌افزار فقط `c1`، `c2`، `s1` و `s2` هستند. عملگرهای حسابی و شیفت در مسیر دادهٔ RTL استفاده نشده‌اند؛ محاسبات اندیس در `generate` صرفاً زمان elaboration انجام می‌شوند.

## پیش از تحویل بخوانید

سه نکتهٔ صورت تمرین با پروژهٔ اول سازگار نیستند و در `docs/01_contract_FA.md` و گزارش PDF صریحاً بررسی شده‌اند:

1. **مانتیس صفر:** حالت پیش‌فرض، متن فاز اول را لفظی اجرا می‌کند: اگر `a[9:0]==0` یا `a[14:10]==0` باشد، ورودی صفر محسوب می‌شود. بنابراین `16'h3C00` نیز در این قرارداد صفر است. پارامتر `ZERO_FRAC_IS_ZERO=0` برای تفسیر جایگزین «مانتیس شامل بیت مخفی ۱» وجود دارد؛ این حالت هم از گردکردن و subnormal پشتیبانی نمی‌کند و پیاده‌سازی کامل IEEE-754 نیست.
2. **نمای ۳۲:** عدد ۳۲ در فیلد ۵بیتی نما قابل نمایش نیست. انتخاب مستند این تحویل، کد سرریز `{sign,5'd31,10'd0}` است. پارامتر `OVERFLOW_EXP` محل تغییر این قرارداد پس از پاسخ TA است. هر دو واحد حسابی از همین سیاست استفاده می‌کنند.
3. **فرادادهٔ بافر:** بافر قبلی شما به ازای هر داده، `wr_dest` و `wr_last` هم ذخیره می‌کند. بافر دادهٔ ۱۶بیتی `ping_pong_buffer` زیر سقف گیت است. نسخهٔ دارای **تمام پورت‌ها و پارامترهای CA1** در `integration/fcnn_ping_pong_buffer.v` ارائه شده و رفتار قانونی آن با CA1 چرخه‌به‌چرخه مقایسه شده است؛ هزینهٔ این نسخه **۴۴۹۹ گیت** است و از سقف ۳۵۴۰ بیشتر است. این اضافه‌هزینه پنهان نشده است.

تغییر پارامتر عددی باید هم‌زمان در DUT و مدل مرجع/تست مورد انتظار اعمال شود. صفرهای خروجی و underflow در این بسته به `+0` تبدیل می‌شوند. آزمون‌ها هر دو تفسیر مانتیس را جداگانه بررسی می‌کنند.

## اجرای تست‌ها

نیازمندی عمومی: Python 3.10 یا جدیدتر و **Icarus Verilog 11 یا جدیدتر** (`iverilog` و `vvp`) در PATH. اجرای طراحی و تولید مدل مرجع به NumPy یا PyTorch وابسته نیست.

از ریشهٔ همین بسته:

```bash
python scripts/run.py
python scripts/count_gates.py --check
python scripts/audit.py
```

دستور دوم به **Yosys** نیاز دارد. در ویندوز در صورت نیاز `py -3` را به جای `python` بنویسید. خروجی‌های تست در `results/icarus/` و فایل‌های موقت در `build/` ساخته می‌شوند. هر خطای کامپایل، assertion، timeout، وکتور ناقص یا نبود پیام PASS، اجرای Python را ناموفق می‌کند.

اجرای کوتاه‌تر و انتخاب گروه:

```bash
python scripts/run.py --quick
python scripts/run.py --groups buffer,cells,helpers
python scripts/run.py --quick --groups fp --wave
```

حالت کامل، ۴۰۴۰۱۴ جفت ورودی برای **هر** عملگر دارد؛ دو DUT با دو سیاست مانتیس هم‌زمان کنترل می‌شوند. حالت کوتاه‌تر نیز ۷۸۲۵۴ جفت دارد. اجرای کامل روی مدل سلولی بدون تأخیر ممکن است چند تا چند ده دقیقه طول بکشد. ساخت waveform کامل، فایل بسیار بزرگی ایجاد می‌کند؛ برای مشاهدهٔ موج از اجرای کوتاه‌تر استفاده کنید.

## اجرای ModelSim / Questa

فایل‌های وکتور کامل از قبل در `tb/vectors/` موجودند؛ مسیر GUI به Python و C++ نیاز ندارد. پوشهٔ جاری ModelSim باید ریشهٔ بسته باشد:

```tcl
set TEST tb_fp16_adder
do run_modelsim.do
```

برای تست‌های دیگر، مقدار `TEST` را به `tb_fp16_multiplier`، `tb_ping_pong_buffer`، `tb_actel_cells` یا `tb_building_blocks` تغییر دهید. اسکریپت در پایان، موج و سیگنال‌ها را باز نگه می‌دارد.

**اجرای ثبت‌شدهٔ این تحویل با Icarus 12.0 و شمارش با Yosys 0.33 انجام شده است. ModelSim در محیط ساخت نصب نبود؛ اجرای موفق آن ادعا نمی‌شود.** سورس RTL با نحو Verilog-2005 نوشته شده و تست‌بنچ‌ها با گزینهٔ SystemVerilog کامپایل می‌شوند.

## شمارش با روش اجرایی TA

کدهای اصلی TA بدون تغییر در `reference/ta_original/` حفظ شده‌اند. آن کدهای C++ وابسته به Windows هستند. جایگزین قابل‌حمل و دارای قفل هم‌زمانی در `scripts/gate_counter.cpp` قرار دارد. با نصب g++ و ModelSim/Questa:

```bash
python scripts/count_modelsim.py
```

این اسکریپت سه فایل `c1.exe`، `c2.exe` و `s2-s1.exe` را می‌سازد، برای **هر ماژول یک DUT تنها** اجرا می‌کند، `gated.txt` را قبل از اجرا صفر می‌کند و نتیجه را با شمارش مستقل مقایسه می‌کند. استفاده از تست‌بنچ عددی اصلی برای شمارش اشتباه است، چون دو نسخهٔ DUT در آن وجود دارد. در PDF نام `s1-s2` نیز آمده، ولی فایل واقعی TA و فراخوانی کتابخانه `s2-s1` است؛ اسکریپت مطابق فایل واقعی عمل می‌کند.
